# 五项修复计划（2026-09-22）

## 范围与约束

- 只修改源码、文档和测试，不修改真实 API Key、待办、便签或对话数据。
- 不提交、不推送、不发布新版本；现有安装包不会被自动替换。
- 安全策略是风险分级和显式授权，不把命令黑名单宣称为沙箱。
- 历史优化保留完整正文，仅移除可重新生成的展示字段；测试使用临时数据。

## 实施顺序

| 阶段 | 具体步骤 | 验收条件 |
| --- | --- | --- |
| 1. 版本一致性 | 建立无副作用版本模块；主程序、安装器、构建工具统一导入；更新维护说明 | 动态修改版本的测试同步影响各入口；源码无第二份版本常量 |

| 3. 模块拆分 | 提取静态工具目录与权限 QML 组件；保留 `ToolContext`、`AiController` 原公开接口，避免一次性大重构 | 原回归通过，新 Python 模块可导入，新增 QML 组件可加载 |
| 4. 历史存储 | 按会话追加；日志与快照绑定；中断恢复；导出合并为兼容快照；导入不混旧日志 | 完整正文不丢失、重启恢复、失败重试、删除不复活、旧备份可导入 |
| 5. 测试编码 | 统一工具标准流和子进程 UTF-8；模拟 GBK 环境 | 字形回归直接运行成功，父子进程输出一致 |
