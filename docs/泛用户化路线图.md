# 小爪泛用户化路线图

结论先行：**当前阶段不缺功能，缺的是"让泛用户能用上"和"让泛用户用得上"。**

功能密度已经远超泛用户需求（7 个页面 + AI Agent + 知识库 + MCP + 自定义工具三档）。
真正卡人的是五个坎，一个都没绕过去。补完这五个，再谈加功能。

---

## 零、先承认一件事

现在这个产品本质上是**你给自己做的超强工具**，不是给泛用户做的产品。证据：

| 现象 | 含义 |
|---|---|
| `ai_mcp_enabled=False` | 连你自己都关着 MCP |
| 17 个自定义工具全是自己造的（8 recipe / 6 note / 3 code） | 泛用户不会写 recipe |
| 知识库 509KB 数据 | 泛用户不会去"导入资料" |
| `ai_max_steps=100`、`ai_level='full'` | 这是重度用户的设置，默认值是 20 / confirm |
| 没有首启引导、没有数据导出、没有自动更新 | 说明目标用户就是"会自己 clone 代码的人" |

这不丢人 —— 但泛用户化意味着要**换一套假设**，而且大概率要做减法。

---

## 一、五个坎（按严重度）

### 坎 1 · AI 必须自备 Key —— 致命

**现状。** `providers.py` 已经做得很好了：DeepSeek / Kimi / 智谱 / 通义 / OpenAI / OpenRouter / Ollama 七家预设，带 `signup_url` 和 `free_hint`。`controller.py:410` 甚至专门写了注释：

> 泛用户点开界面就该看到一个「去哪拿 Key」的按钮，而不是先做一道七选一的选择题。其他家收在「想用别的」后面。

判断完全正确。但终点仍然是让用户走完：

```
注册账号 → 实名认证 → 充值 → 找到 API Keys 页 → 复制 → 回来粘贴
```

**能走完这四步的人，本来就会用 ChatGPT。** 泛用户在这一步流失的比例最高，而 AI 是小爪的核心卖点 —— 没跨过这一步的用户，感知到的产品价值只剩一半。

**三个方案，按彻底程度排序：**

| 方案 | 做法 | 成本 | 判断 |
|---|---|---|---|
| **官方中转** | 你出 key 做服务端代理，客户端只填账号 | 服务器 + 计费 + 被滥用风险 | 最彻底，但要投入 |
| **共享额度池** | 免费用户每天 N 次（N 取 10~20），付费解锁 | 同上，额外需配额系统 | 中转的进阶版，适合做转化 |
| **不提 AI 也能用** | 把非 AI 功能（待办/专注/便签/提醒）推到前台当卖点 | 几乎零成本 | **保底，必须先做** |

**建议：先做 3，再做 1。** 方案 1 要花钱花时间；方案 3 只是改包装和引导。

方案 3 的具体动作：
- 首启引导第一屏就说「不用配任何东西，现在就能用」；
- `TodayPage` 里把番茄钟/待办放到最显眼处，AI 入口后置；
- 产品介绍页（GitHub README 首屏、下载页）把"离线可用的桌面效率工具"当第一卖点，"AI 操作电脑"当第二卖点。

**注意：不要为了泛用户去破解"免费无限用"。** DeepSeek 的中转成本虽低，但一个公开的免费 key 会在几小时内被薅光。额度池是必需的不是可选的。

### 坎 2 · 没有首次启动引导 —— 致命

**现状。** 全仓 grep `first_run|onboard|welcome|初次|第一次|新手|教程|tour`，**零命中**（只有 AI 页里一句"第一次用？两步：拿 Key → 粘到下面"）。

用户下载安装、双击运行，看到的是：一只宠物飘在屏幕上，没有任何说明。

他不知道：拖动可以换位置、双击能开工作台、右键有菜单、有全局热键、有七个页面。
README 里全写了 —— **但泛用户不看 README。**

**要做的事：三步引导，不超过 3 屏，每屏一个动作。**

| 屏 | 内容 | 关键 |
|---|---|---|
| 1 | 这是小爪 —— 拖我换位置、双击开工作台、右键有菜单 | 用真实的宠物做插图，不是截图 |
| 2 | 你的东西都在本地 —— 待办 / 专注 / 便签 / 提醒，不联网也能用 | 建立隐私信任 |
| 3 | 想让我更聪明？给个 Key —— 或者直接跳过 | **必须能跳过，且跳过之后产品依然完整** |

技术实现：`store.py` 的 settings 里加 `onboarding_done: False`，`Main.qml` 启动时判空则显示引导层。半天工作量。

补充：`tools/` 目录下有 `layoutcheck.py` / `dpidiag.py` / `fontcheck.py` 这类脚本，说明你在意不同 DPI 下的显示 —— 引导层同样要在 125% / 150% 缩放下验证。

### 坎 3 · 数据没有导出 / 导入

**现状。** 设置页「数据」区块只有：显示数据文件路径 + 「打开数据文件夹」按钮。全仓 grep `导出|导入|备份|restore`（排除 `ai/`），只命中 `backend.exportSummary()` —— 那是复制"今日总结"文本，不是数据备份。

`store.py` 有 `pet_data.json` + `pet_data.backup.json`（每次保存前留一份），但那是**防写坏的**，不是**防丢的**。

**用户场景（都会真实发生）：**
- 换电脑 → 数据全没，从零开始
- 重装系统 → 同上
- 多台机器（公司 + 家里）→ 无法同步

**要做的事：**

```
导出：打包成 zip                                     ← 已实现（pawpet/datatransfer.py）
  ├─ pet_data.json
  ├─ extensions.json
  ├─ theme.json
  ├─ conversations.json
  ├─ pet_data.enc（可选：知识库）    ← 没做，见下方注意 2
  └─ pawpet-manifest.json（版本、导出时间、条目数）
导入：校验 schema 版本 → 备份现有数据 → 覆盖 → 重启提示   ← 已实现，
      但**最后一步换成了「当场重载」**，见下方「实现后的修正」
```

**已实现（2026-09-18）。** 五个卡点里第 3 个。写法和上面的草案有三处不同，
都是实现时才发现的问题：

1. **导入之后必须当场重载内存，不能只提示「重启后生效」。** 草案里那句
   「重启提示」是错的。`import_bundle` 只换磁盘文件，而 `store.state`、
   五个 Model 的 `_visible`、AI 侧的内存对话副本还都是旧的 —— 用户随后的
   任何一次 `flush()`（改个设置、勾个待办）都会把旧数据整份写回去。
   **导入看上去成功，实际白做，且全程不报错。** 这是本次最值钱的一个修正，
   做法是 `Backend.reloadData()`，用 `tools/reloadtest.py` 钉住。
2. **AI 的对话历史要单独处理。** 它有一份内存副本 + 一个「2 秒后写盘」的
   延迟任务，重载时必须先掐定时器、再清脏标记、最后才重读。
3. **校验要验到数据本身，不能只验 manifest。** 草案里的「校验 schema 版本」
   只覆盖了 manifest。一个 manifest 完好、`pet_data.json` 却被截断的包
   （网盘传到一半）会覆盖掉用户数据，然后 store 读不动、回退到默认空状态 ——
   而救命备份叫 `pet_data.before-import.json`，不是 store 会自动读的那个名字，
   程序不会自己恢复。所以现在**先验内容再动文件**，坏包一个字节都不写。

**顺带加的一条安全规则：** 导入可以把 AI 权限收紧，但不许放松。备份文件是
能被别人转发的，`ai_level` 一旦能跟着文件走，「完全自动」这一档就等于把键盘
鼠标交出去 —— 用户只会看到「导入完成」。规则改成「取导入前和备份里更紧的
那个」，用户想放宽是自己去设置页点。

**注意两点：**
1. `.env`（API Key）**默认不要打包**，或者打包前明确问一次。`store.py:71` 的注释也写了 Key 不进 `pet_data.json`，别在导出这里破功。→ **已按「不打包装」实现**，`datatranstest.py` 里有断言钉住。
2. 知识库 509KB 已经比其它所有数据加起来还大。单文件全量落盘的性能问题（`store.save()` 每次 ~1.7MB I/O）在泛用户这里会放大 —— 建议导出的同时把 `knowledge.docs` 拆到独立文件。→ **没做**，留到后面。

**不建议做云同步。** README 明确承诺"本机存储不上传"，泛用户对桌面宠物的隐私敏感度高于效率工具。云同步一上，这个承诺就破了。用 zip 导入导出足够。

### 坎 4 · 没有自动更新

**现状。** `backend.version` 只是个只读属性，没有任何更新检查。

**后果：** 你后续所有的修复和改进，只有新下载的用户能拿到。老用户永远停在装机那个版本 —— 包括上一轮评审里那两个 P0 安全缺陷。

**分两档做：**

| 档 | 做法 | 工作量 |
|---|---|---|
| 最小可用 | 启动时请求一个 `version.json`，有新版弹一条提示 + 打开下载页 | 半天 |
| 完整 | 下载 + 校验 + 静默替换 exe（Windows 需"改自己名字再替换"的技巧） | 2~3 天 |

**先做最小可用。** 关键是**把版本号暴露出来**（`update.json` 放 GitHub Release 或你自己的静态页就行）。

**必须注意：** 更新会碰 `pet_data.json` 的结构。`store.py` 已有 `SCHEMA_VERSION`，更新逻辑里要带迁移函数，否则老用户升级后数据读不出来 —— 这比不更新更糟。

---

### 坎 5 · 没有代码签名

**现状。** `build/pawpet.spec:121` 和 `build/setup.spec:62` 都是 `codesign_identity=None`，`tools/build.py` 里没有任何签名步骤。

**后果：** Windows SmartScreen 会弹"Windows 已保护你的电脑 —— 未知发布者"。**看到红字关掉窗口的人远多于点「更多信息 → 仍要运行」的人。**

**现实约束：** 个人开发者签名证书不便宜（OV 一年几百到上千，EV 更贵），而且现在很多 CA 要求企业资质。

**折中做法：**
1. 下载页明确写清 SmartScreen 绕过步骤（配截图）；
2. 用 winget / scoop 分发 —— 包管理器下载的不触发 SmartScreen 警告；
3. 规模起来后再考虑买证书。

## 二、然后才是：该加什么、该藏什么

这里必须先回答一个问题 —— **你说的"泛用户"是谁？**

小爪现在的形态是「宠物外壳 + 效率工具内核 + AI Agent 引擎」，骑在两条路中间。两条路的拓展方向完全不同：

| | A. 效率助手路线 | B. 桌面陪伴路线 |
|---|---|---|
| 泛用户 | 想省时间的打工人 | 想要点情绪价值的年轻人 |
| 竞品 | Raycast / Copilot / 各类 AI 助手 | QQ 宠物类 / 桌面摆件 |
| 现状 | 红海，但你的桌面宠物形态是差异化 | 变现难，但门槛低 |
| 可复用资产 | **AI Agent 层 11894 行全部用上** | 基本浪费 |
| 该加 | 场景化快捷指令、结果可拖出到任意窗口、历史可搜索、指令市场 | 情绪系统、主动关怀、装扮/皮肤、分享卡片、成长记录 |
| 该藏 | MCP、自定义工具、知识库、步数设置 | 同上 + 权限等级 |

**我的判断：走 A，保留宠物外壳。**

理由三条：
1. 你已经把 11894 行 AI Agent 代码写完了，这是真资产。走 B 等于扔掉。
2. B 路线的付费意愿极低，且 QQ 宠物类产品已经反复验证过变现困难。
3. **桌面宠物形态在 A 路线里是优势不是负担** —— Raycast 要靠快捷键呼出，你是常驻的，天然有"随时唤醒 + 陪伴感"两个属性。这是竞品抄不走的。

**但走 A 必须接受一个前提：AI 得开箱即用。** 否则核心功能废掉，剩下的待办/番茄钟在竞品里随便找。

## 三、该做的减法（这才是提升留存最快的动作）

泛用户不需要下面这些。**不是删掉，是收进「高级模式」开关后面：**

| 功能 | 现在的状态 | 建议 | 实际做成了什么 |
|---|---|---|---|
| MCP 服务 | 你自己都关着 | 收进高级模式 | ✅ 整张卡片收起（AI 页） |
| 知识库 | 509KB 数据是你在用 | 收进高级模式 | ✅ 整块收起（AI 页「模型设置」展开区里） |
| 自定义工具（三档） | 17 个是你自己造的 | 收进高级模式，但保留"记住这个做法"的入口（note / recipe 有泛用户价值，code 没有） | ⬜ 没动 —— 见下方「没收的三样」 |
| 权限四级 / 步数 / 扩展级别 | 泛用户看不懂也不会调 | 收进高级模式，默认值改保守 | ⬜ 只收了「扩展级别」的入口，其余没动 |
| 危险命令黑名单 | 泛用户不知道有这东西 | 保留，但别写在宣传里（先修好再讲，见评审报告 P1） | ✅ 保留（P1 那批已修） |

**默认界面只留：今日 / 专注 / 待办 / 便签 / 提醒 / AI（简化版）/ 设置。**

### 实现后的修正（2026-09-18）

开关落在设置页最下面（「关于」前面），默认关。打开后 AI 页多出两块。
做法上偏离草案的三处，都是动手时才发现「照草案做会出事」：

1. **不是所有"泛用户看不懂的"都该收。** 草案把「步数」和「权限等级」一起划走了，
   但「执行步数」是有实际用处的：一轮任务干到一半停了，用户得知道去哪儿调大。
   收了他就卡在"为什么只干了 5 步就停"上。**判断口径是「第一次打开会不会看不懂」，
   不是「我用不用得上」。** `tools/advancedtest.py` 里有一条反向断言专门钉这个 ——
   把步数藏起来它会红。
2. **「模型设置」绝对不能收。** 没配 Key 的新用户全靠它填接口地址，
   收了他就卡在「还没有配置模型」上出不去，而首启引导第 3 屏刚好指向这里。
   这条也有断言守着。
3. **位置也是过滤。** 高级模式开关放在设置页最底部 —— 越不常用的越靠后，
   泛用户滚不到，也就不会被这个词绊住。测试里钉住了：`title: "高级模式"`
   这张卡必须排在 `title: "关于"` 前面。

**没收的三样：** 自定义工具（三档）、权限四级、扩展级别的配置面板。
理由：它们要么在别的页面（扩展级别在扩展页），要么收了会让「高级模式」
本身变成一个需要解释的东西 —— 一个开关后面塞四五块，等于把复杂度搬了个家。

少即是多。泛用户的第一次打开体验，决定他会不会有第二次。

## 四、优先级

**① ~ ④ 已实现（2026-09-18），⑥ 也已实现。** 代码在 `pawpet/` 下，回归在 `tools/` 下，
清单和口径见 README。「工作量」那一列是事前的估计，实际 ①~④ 加起来一天以内，
⑥ 半天以内 —— 都是估计偏保守。

| # | 事项 | 工作量 | 状态 | 为什么排这个位置 |
|---|---|---|---|---|
| 1 | 首启三步引导（可跳过） | 0.5 天 | ✅ 已实现 | 成本最低、收益最直接 |
| 2 | 产品卖点重排（不配 Key 也有用） | 0.5 天 | ✅ 已实现 | 让没 Key 的用户也能感知价值 |
| 3 | 数据导出 / 导入 | 1~2 天 | ✅ 已实现 | 泛用户换电脑是高频场景 |
| 4 | 自动更新（最小版） | 0.5 天 | ✅ 已实现 | 否则老用户永远拿不到修复 |
| 5 | 官方中转 / 额度池 | 1~2 周 | ⬜ 未做 | 最彻底，但要花钱，放后面 |
| 6 | 高级模式收纳 | 2~3 天 | ✅ 已实现 | 提升首屏清晰度 |
| 7 | 代码签名 / winget 分发 | 取决于预算 | ⬜ 未做 | 影响下载转化率 |
| 8 | 情境化快捷指令（A 路线拓展） | 持续 | ⬜ 未做 | 地基补完再说 |

**剩下的两条（⑤ 和 ⑦）都不是代码问题** —— 一个要服务器和计费，一个要钱要企业资质。
在没有预算和资质之前，能靠写代码推进的项已经做完了。

上级评审（`评审-小爪AI-Agent层.md`）里的两处 P0 已在后续轮次处理：
`code` 档自我扩权闭环**已修**（`Risk.CRITICAL` 三处挂点 + 回归钉住）；
`MAX_LEVEL_DEFAULT = LEVEL_CODE` 经复核是**我的误判**，已撤回（`tools/exttest.py:148`
有断言说明那是设计意图）。那一轮顺带发现并修掉一条更值钱的真缺陷：
`MemoryBook.save()` 整份替换 `state["memory"]`，会把 `_observe_app` 攒的
`app_usage` 静默吃干净。

## 五、最后一句

**在这个阶段，继续加功能是负收益。** 每加一个功能，首屏就更复杂一点，泛用户的理解成本就更高一点。

功能已经够多了，多到你自己都关掉了其中一部分（MCP）。

下一步该做的不是写代码，是**找 20 个不用 AI 工具的普通人装上小爪，看他们第一天卡在哪**。你现在所有的判断，包括我这份，都是从代码里推出来的 —— 真实用户会在你没想到的地方卡住。
